# 存档同步使用说明

## 交付状态

已按照确认后的需求编写 Android Java 实现。本次没有生成测试用例，没有执行 Gradle 构建、启动应用或连接实际对象存储进行验证；相关校验由你进行。

## 使用顺序

1. 打开侧边栏的“S3 配置”。旧版本的 Bucket 和访问凭证会自动保留。
2. 填写 S3 Endpoint、Region、Bucket、Access Key 和 Secret Key。Endpoint 支持 HTTP、HTTPS 和端口，不包含 Bucket、路径或查询参数。
3. 七牛必须使用对应区域的 S3 服务地址及 S3 Bucket 名称，不能继续使用七牛原生上传、资源管理或下载域名。示例：`http://s3.cn-east-1.qiniucs.com`，Region 为 `cn-east-1`；请以服务商实际配置为准。
4. 默认勾选“路径式访问”，请求为 `Endpoint/Bucket/Key`，适用于 IP 地址和多数自建服务；服务要求 `Bucket.Endpoint/Key` 时取消勾选。使用 IP 时必须勾选。
5. 保存配置。第一次从旧协议切换到 S3 时清除上传水位与逐文件同步记录，本地文件、目录授权和映射配置保留；下一次上传按首次同步处理。
6. 打开侧边栏的“添加路径”，通过系统目录选择器授权本地目录，填写远端前缀，例如 `saves/device-a/`，以及格式，例如 `sav,srm,state`；`*` 表示全部文件。
7. 点击“保存并上传”，开始首次上传。后续在映射卡片点击“上传到云端”或“从云端下载”。原有映射可以直接继续使用。
8. 下载遇到远端较旧、时间相同但内容不同或时间未知的已有本地文件，会询问是否覆盖；默认跳过。

上传同名对象直接覆盖。删除映射只删除配置和同步记录，不删除任何实际文件。

## 同步记录规则

- 新映射首次扫描全部匹配文件，未有成功记录的文件不会因时间较早而被漏传。
- 未变化的上传文件按最近一次成功的本地修改时间和大小跳过。
- 新增、上次失败、修改时间或大小变化的文件会进入上传；即使修改时间被调回较早时间，也保守重传。
- 映射保存整轮上传成功的扫描截止时间，同时使用逐文件成功记录处理边界时间与部分失败重试，不以一条全局时间决定所有文件是否已同步。
- 上传失败、取消或扫描不完整时不推进成功水位。扫描截止之后更新的文件计入“待下次”，不会冒充已上传。
- 上传读取得到本地快照，传输结束后重新检查本地内容；文件仍变化时标记失败，留待重试。
- 只通过修改时间和大小跳过的历史上传文件，不保证识别“内容变化但修改时间及大小完全不变”的特殊改写。
- 下载成功记录文件落地后的本地时间、大小、内容摘要和远端 ETag。再次上传先核对内容，避免因系统落地时间改变而重复回传；再次下载时使用 ETag 和大小比对更新记录。
- 系统目录 URI 没有通用的修改时间写入接口；当前通过源时间与本地下载基线对应关系参与新旧比较，不直接修改提供方文件时间。
下载时先读取远端清单中的对象 Key、ETag 和大小，再对照本机的同步记录与本地文件修改时间、大小。远端版本和本地状态都未变化的文件会直接跳过，不再逐个发送 HEAD/GET；只有新文件、本地文件变化或远端版本变化时，才查询元数据并下载校验。

## 远端元数据

本应用上传时使用两个自定义元数据字段：

- `x-amz-meta-sgs-mtime`：源文件修改时间，UTC 毫秒；`0` 表示未知。
- `x-amz-meta-sgs-sha256`：上传快照的 SHA-256。

对象的 Last-Modified 不当成源存档修改时间。S3 ETag 仅用作不透明版本标识，不假定等于 MD5 或七牛哈希。上传发送 Content-MD5 与签名的 SHA-256，完成后通过 HEAD 核对 ETag、大小和自定义元数据。下载通过 If-Match 固定版本，检查返回 ETag、大小及可用的 SHA-256。旧原生协议对象或其他工具上传的对象可能没有这些元数据：没有 SHA-256 时只能核对版本与大小，覆盖已有本地文件时按源时间未知处理，仍需确认。

## 下载与恢复

1. 下载到应用私有缓存，校验大小、ETag，以及可用的 SHA-256。
2. 比较本地内容与源修改时间，必要时显示确认。
3. 确认后重新检查本地内容及远端版本，避免用过期决定覆盖文件。
4. 对已有文件先在应用私有目录保存原件备份，并持久化恢复日志。
5. 写入后重新读取内容校验；失败时尝试恢复原件。
6. 应用异常中断后，下次启动优先恢复上次未完成的写入；恢复未完成时保留备份，阻止后续传输破坏恢复资料。

由于不同目录提供方能力不同，不承诺 SAF 文件替换的全局原子性。执行下载前建议暂停正在写入存档的游戏，减少外部并发写入。处于写入／恢复临界阶段的单个文件会先完成或恢复，再响应取消。

如果页面提示恢复失败，可以重新授权原目录，再点击“重新尝试恢复上次写入”。恢复资料位于应用私有 `files/recovery/`，不要清除应用数据或卸载后再尝试恢复。

## 一期边界

- 同一时间串行执行一个任务；应用内任务可跨页面旋转继续，系统结束进程后由用户重试。
- 不包含后台服务、定时同步、实时监听和开机自动同步。
- 不传播删除，不做历史版本管理和内容合并。
- 不申请 Root 或特殊存储权限；系统不允许授权的目录不能通过本期功能绕过限制。
- 支持 HTTP 和 HTTPS，Android 已允许明文网络访问；不自动跟随重定向，服务地址应填最终地址。
- 配置页屏蔽截图及系统自动填充；密钥不进入普通配置或日志，不提供明文凭证导出。
- 凭证加密信息依赖本机 AndroidKeyStore；系统安全存储失效时需要重新填写。
- 修改 Endpoint、Region、Bucket、访问方式或映射范围会重置对应成功记录；仅更换访问密钥或映射名称不重置。
- 使用 ListObjects V1 分页、HeadObject、PutObject 和 GetObject；账号需具备列举、读取和覆盖上传权限。所有请求均使用 S3 V4 签名。
- 远端更新判定依赖 S3 列表返回的 ETag 与对象大小；服务端应为同一对象版本提供稳定 ETag。版本变化后仍通过 HEAD/GET 检查元数据和文件内容。
- 普通 PutObject 单文件最多 5 GiB，实际限制以服务商为准；暂不包含分片上传和断点续传。

## 工程准备

项目使用 DrawerLayout、Activity、Lifecycle、Gson、OkHttp、AWS Android SDK Core（仅使用其 V4 签名器）和 Lombok 依赖。Java 源代码兼容级别仍为 Java 8，Android 最低版本保持 API 21。

当前工程原有 Gradle 启动脚本引用 `gradle/wrapper/gradle-wrapper.jar`，但初始目录未提供该文件。若你通过该脚本构建，需要在自己的构建环境补齐对应 Wrapper，或使用已安装且兼容的 Gradle。本机未运行构建，也未下载或执行构建工具。GitHub Actions 已使用独立安装的 Gradle 8.2 绕过 Wrapper，详见《GitHub云端打包.md》。
