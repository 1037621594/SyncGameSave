# 存档同步使用说明

## 交付状态

已按照确认后的需求编写 Android Java 实现。本次没有生成测试用例，没有执行 Gradle 构建、启动应用或连接实际七牛空间进行验证；相关校验由你进行。

## 使用顺序

1. 打开侧边栏的“七牛配置”。
2. 填写 Bucket、AccessKey、SecretKey、上传服务地址、资源管理地址、资源列举地址和下载域名。
3. 服务地址与下载域名可填写 HTTP 或 HTTPS 域名，可带端口，不包含额外路径或查询参数。服务域名需要与你的空间区域对应；默认地址可在配置页修改。
4. 按空间实际访问方式勾选“私有空间”，保存。
5. 打开侧边栏的“添加路径”，填写映射名称，通过系统目录选择器授权本地目录。
6. 填写远端前缀，例如 `saves/device-a/`，以及格式，例如 `sav,srm,state`；`*` 表示全部文件。
7. 点击“保存并上传”，开始首次上传。后续在映射卡片点击“上传到云端”或“从云端下载”。
8. 下载遇到远端较旧、时间相同但内容不同或时间未知的已有本地文件，会询问是否覆盖；默认跳过。

上传同名对象直接覆盖。删除映射只删除配置和同步记录，不删除任何实际文件。

## 同步记录规则

- 新映射首次扫描全部匹配文件，未有成功记录的文件不会因时间较早而被漏传。
- 未变化的上传文件按最近一次成功的本地修改时间和大小跳过。
- 新增、上次失败、修改时间或大小变化的文件会进入上传；即使修改时间被调回较早时间，也保守重传。
- 映射保存整轮上传成功的扫描截止时间，同时使用逐文件成功记录处理边界时间与部分失败重试，不以一条全局时间决定所有文件是否已同步。
- 上传失败、取消或扫描不完整时不推进成功水位。扫描截止之后更新的文件计入“待下次”，不会冒充已上传。
- 上传读取得到本地快照，传输结束后重新检查本地内容；文件仍变化时标记失败，留待重试。
- 只通过修改时间和大小跳过的历史上传文件，不保证识别“内容变化但修改时间及大小完全不变”的特殊改写。
- 下载成功记录文件落地后的本地时间、大小和内容摘要。再次上传先核对内容，避免因系统落地时间改变而重复回传。
- 系统目录 URI 没有通用的修改时间写入接口；当前通过源时间与本地下载基线对应关系参与新旧比较，不直接修改提供方文件时间。

## 远端元数据

本应用上传时使用两个自定义元数据字段：

- `x-qn-meta-sgs-mtime`：源文件修改时间，UTC 毫秒；`0` 表示未知。
- `x-qn-meta-sgs-sha256`：上传快照的 SHA-256。

对象自身的上传时间只作辅助信息，不当成源存档修改时间。已有七牛文件如果不是本应用上传，可能缺少元数据；其内容下载仍须通过大小和 ETag 校验，覆盖本地已有文件时按时间未知处理。

## 下载与恢复

1. 下载到应用私有缓存，校验大小、ETag，以及可用的 SHA-256。
2. 比较本地内容与源修改时间，必要时显示确认。
3. 确认后重新检查本地内容及远端版本，避免用过期决定覆盖文件。
4. 对已有文件先在应用私有目录保存原件备份，并持久化恢复日志。
5. 写入后重新读取内容校验；失败时尝试恢复原件。
6. 应用异常中断后，下次启动优先恢复上次未完成的写入；恢复未完成时保留备份，阻止后续传输破坏恢复资料。

由于不同目录提供方能力不同，不承诺 SAF 文件替换的全局原子性。执行下载前建议暂停正在写入存档的游戏，减少外部并发写入。处于写入／恢复临界阶段的单个文件会先完成或恢复，再响应取消。

如果页面提示恢复失败，可以重新授权原目录，再点击“重新尝试恢复上次写入”。恢复资料位于应用私有 `files/recovery/`，不要清除应用数据或卸载后再尝试恢复。

## 一期边界

- 同一时间串行执行一个任务；应用内任务可跨页面旋转继续，系统结束进程后由用户重试。
- 不包含后台服务、定时同步、实时监听和开机自动同步。
- 不传播删除，不做历史版本管理和内容合并。
- 不申请 Root 或特殊存储权限；系统不允许授权的目录不能通过本期功能绕过限制。
- 支持 HTTP 和 HTTPS，Android 已允许明文网络访问；不自动跟随重定向，服务地址应填最终地址。
- 配置页屏蔽截图及系统自动填充；密钥不进入普通配置或日志，不提供明文凭证导出。
- 凭证加密信息依赖本机 AndroidKeyStore；系统安全存储失效时需要重新填写。
- 修改远端目标或映射范围会重置对应成功记录；单纯修改名称不重置。

## 工程准备

本次新增了 DrawerLayout、Activity、Lifecycle、Gson、OkHttp 和 Lombok 依赖。Java 源代码兼容级别仍为 Java 8，Android 最低版本保持 API 21。

当前工程原有 Gradle 启动脚本引用 `gradle/wrapper/gradle-wrapper.jar`，但初始目录未提供该文件。若你通过该脚本构建，需要在自己的构建环境补齐对应 Wrapper，或使用已安装且兼容的 Gradle。本机未运行构建，也未下载或执行构建工具。GitHub Actions 已使用独立安装的 Gradle 8.2 绕过 Wrapper，详见《GitHub云端打包.md》。
