# 存档同步需求与实施方案（已确认）

- 项目：SyncGameSave
- 编写日期：2026-10-27
- 当前阶段：需求已于 2026-10-27 确认，已按一期方案编写实现；构建、运行及功能校验由项目负责人执行。
- 项目现状：Android Java 工程，当前只有空白主页面；尚无侧边栏、同步逻辑或七牛配置。

## 1. 目标与范围

应用只负责把用户配置的本地文件上传到七牛对象存储，以及从七牛下载回本地。

一期包含：

1. 增加侧边栏及“添加路径”菜单。
2. 配置本地目录、七牛空间内的远端目录和文件格式。
3. 配置保存成功后，自动上传该映射下所有未同步文件。
4. 记录本地最后成功上传时间，后续只上传新增、未成功同步或在此之后更新的文件。
5. 支持用户手动执行“上传到云端”和“从云端下载”。
6. 下载覆盖前比较文件更新时间；远端比本地旧时，必须二次确认。
7. 展示同步进度、结果和失败原因，并允许重试。

一期不包含：后台定时同步、目录实时监听、文件内容合并、多端锁、历史版本管理、远端与本地删除联动。上传与下载是两个明确操作，不自动执行双向同步。

> 本文把“OSS”统一称为“七牛对象存储”；远端目录指空间内的对象 Key 前缀。

## 2. 页面与交互

### 2.1 主页面与侧边栏

主页面改为顶部工具栏、侧边栏和路径映射列表。

侧边栏菜单：

- **添加路径**：打开映射配置页面。
- **七牛配置**：配置连接信息和访问凭证。

每条映射在主页面展示：

- 映射名称、本地目录、远端目录、文件格式。
- 最后一次完整上传成功时间；从未成功时显示“尚未同步”。
- 当前状态：空闲、扫描中、上传中、下载中、等待确认或失败。
- 操作：上传到云端、从云端下载、编辑、删除配置。

删除配置只移除映射及其本地同步记录，不删除本地文件或远端对象。删除前进行确认。

### 2.2 七牛配置

建议包含：

| 字段 | 说明 |
| --- | --- |
| 空间名称（Bucket） | 必填，实际存放文件的七牛空间 |
| 存储区域／服务地址 | 按所选接入方案填写或选择 |
| 下载域名 | 用于构建下载地址，按空间访问方式配置 |
| AccessKey、SecretKey | 个人使用场景下的本机凭证配置，输入时隐藏显示 |
| 空间访问方式 | 私有或公开；私有空间下载需要授权 |

凭证仅供本机同步使用，不硬编码进源码，不打印到日志，不以明文写入普通配置。实现时结合 Android 系统安全存储方案保存；不承诺在受控或已破解设备上绝对安全。

本期默认直连七牛，不新增服务端。具体 SDK、区域参数、上传覆盖策略、元数据写入及私有下载签名方式，在开工时根据七牛官方文档确认后确定。

### 2.3 添加／编辑路径

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 名称 | 是 | 用于识别映射，例如“模拟器存档” |
| 本地目录 | 是 | 通过系统目录选择器选取，并持久保存可用的访问授权 |
| 远端目录 | 是 | Bucket 内的 Key 前缀，例如 `saves/device-a/game-a/` |
| 文件格式 | 是 | 扩展名列表，例如 `sav,srm,state`；`*` 表示全部文件 |
| 包含子目录 | 是 | 默认开启，递归扫描并保留相对目录结构 |

保存按钮文案建议为“保存并上传”。

保存流程：校验配置 → 持久化配置 → 扫描匹配文件 → 自动执行增量上传 → 展示结果。连接失败时保留配置和失败状态，用户可稍后重试。

编辑名称不重置同步记录；修改本地目录、远端目录、格式范围、递归范围或目标空间后，重新建立该映射的扫描基线，确保新范围内的文件不会因为旧时间记录而漏传。

## 3. 目录映射与文件筛选

示例：

```text
本地目录：用户选择的 GameSave 目录
远端目录：saves/device-a/
文件格式：sav,srm

GameSave/alpha.sav          -> saves/device-a/alpha.sav
GameSave/game-b/slot1.srm   -> saves/device-a/game-b/slot1.srm
GameSave/readme.txt         -> 不同步
```

规则：

- 扩展名大小写不敏感，允许输入 `.sav` 或 `sav`，保存时统一整理。
- 一期仅支持扩展名筛选和 `*`，不支持正则表达式及复杂通配符。
- 格式不能为空；无扩展名文件只有选择 `*` 时才匹配。
- 保留相对目录和文件名，不平铺目录，避免同名文件互相覆盖。
- 远端前缀统一使用 `/`，规范化前后分隔符；拒绝 `..` 等越界路径。
- 下载只处理当前映射前缀内、符合格式与递归配置的文件。
- 不创建空目录对象；不跟随会跳出授权目录的链接。
- 禁止完全重复的映射；配置存在重叠、可能命中同一个远端 Key 时提示冲突。
- 同一 Bucket 内的重叠前缀，仅在完整相对路径及筛选规则能避免冲突时允许保存。

## 4. 本地记录与时间定义

### 4.1 映射记录

每条映射独立保存：映射 ID、名称、本地目录 URI、远端前缀、格式列表、是否递归、目标七牛配置、最后完整上传成功时间、最近一次任务结果。

### 4.2 文件记录

为保证部分失败后的重试和新增文件识别，还需要按“映射 ID + 相对路径”保存最小文件同步记录：

- 最近成功上传或下载的状态及方向。
- 最近成功同步时的本地修改时间、文件大小。
- 远端源文件修改时间、对象版本标识或内容摘要（以接入能力为准）。
- 失败状态及简要原因。
- 如系统无法恢复下载文件的修改时间，保存下载后的本地实际修改时间和对应的源文件修改时间。

这些记录用于防止漏传及识别本应用刚下载的文件，不扩展为历史版本功能。

### 4.3 时间口径

- 所有持久化时间统一为 UTC 时间戳，界面按设备时区展示。
- **文件修改时间**：文件内容所属版本的修改时间，用于比较新旧。
- **对象上传时间**：上传到七牛的时间，不等于源文件内容的修改时间。
- **最后完整上传成功时间**：某次完整成功任务的扫描截止时刻，用作下一轮增量筛选水位。

上传时应将源文件修改时间写入可随对象读取的元数据。不能只拿七牛对象上传时间与本地文件修改时间比较，否则旧存档重新上传后可能被误判为新存档。

不同设备时间可能存在偏差，一期按记录时间比较，不实现跨设备时钟校准。缺少可靠时间时不得默认静默覆盖，具体见下载规则。

## 5. 上传流程

### 5.1 首次同步

配置首次保存后，递归扫描授权目录内所有匹配文件，上传到对应远端 Key。即使文件修改时间很早，只要没有成功同步记录，也属于待上传文件。

上传到同名远端 Key 时覆盖原对象；此行为是用户要求的“上传覆盖”，一期不增加上传方向的新旧确认。

### 5.2 后续增量同步

每次任务开始时记录扫描截止时刻 `T`，读取上一次完整成功水位 `L`。

以下文件进入上传队列：

1. 从未成功同步的新文件，或者之前失败的文件。
2. 本地修改时间晚于 `L` 且不晚于 `T` 的文件。
3. 时间等于边界但文件记录表明发生变化的文件；扫描边界保留容差，并通过文件记录去重，避免文件时间精度导致漏传。
4. 本地修改时间不可信、无法读取时，保守重新上传该文件，不以 `0` 当成正常时间跳过。

本应用刚下载且没有再次修改的文件，通过下载基线记录排除无意义的立即回传。

仅依赖“修改时间晚于水位”无法识别用户手工保留旧时间的内容改动。一期保证正常新增和修改时间变化场景；内容变化但时间、大小均不变的情况，不承诺识别。若后续要求完全识别，需要额外内容摘要扫描。

### 5.3 成功、失败和并发修改

- 每个文件上传成功后立即保存该文件成功记录。
- 整轮扫描和上传全部成功后，才把映射水位推进到 `T`，不能写成任务结束时刻。
- 有文件失败、扫描不完整、授权失效、任务取消或应用中断，不推进整轮水位，保留重试信息。
- 下一轮结合文件成功记录跳过已经成功且未变化的文件，并补传失败项。
- 上传前后检查文件时间和大小；上传期间发生变化时，不把当前版本标记为已同步，保留为待重试。
- 扫描截止时刻之后新增或修改的文件留待下一轮；不因当前任务结束较晚而跳过。
- 对无法获得稳定读取内容的文件，本轮跳过并显示原因，不推进完整成功水位。
- 同一映射同一时刻只允许一个上传或下载任务。

## 6. 下载流程与二次确认

用户点击“从云端下载”后，列出当前映射前缀下的全部对象，处理完整分页，按配置过滤后逐个比较。

### 6.1 下载判断表

| 场景 | 默认行为 |
| --- | --- |
| 本地文件不存在 | 直接下载并按相对路径创建目录 |
| 远端源文件修改时间晚于本地有效修改时间 | 下载并覆盖 |
| 远端源文件修改时间早于本地有效修改时间 | 必须弹出二次确认；默认跳过 |
| 时间相同，且同步记录或可信摘要能确认版本一致 | 跳过 |
| 时间相同，但无法确认版本一致或已知内容不同 | 提示冲突，由用户确认覆盖或跳过 |
| 远端元数据缺失／本地时间不可读取，无法可靠比较 | 显示“无法判断文件新旧”，确认后才覆盖已有本地文件 |

“本地有效修改时间”优先使用真实文件修改时间。如果该文件是本应用下载且之后没有改动，但目录提供方不支持恢复修改时间，则使用已记录的源版本时间；检测到本地变化后，恢复使用当前本地修改时间。

### 6.2 确认弹窗

当远端比本地旧时，明确显示：

```text
远端文件早于本地文件，覆盖可能丢失较新的存档。

文件：game-b/slot1.srm
本地更新时间：2026-10-27 20:30:00
远端文件更新时间：2026-10-26 18:00:00

[跳过] [仍然覆盖]
```

按钮默认选择“跳过”。可提供“对本次任务剩余同类冲突使用此选择”，仅限本次任务，下一次下载仍须重新确认。用户没有选择或任务中断时，不执行覆盖。

显示确认后、真正替换前再次检查本地文件是否变化；若又发生修改，重新比较并在需要时再次确认，避免使用过期的覆盖决定。

### 6.3 下载落地

- 先下载到临时文件，确认传输完整、校验通过后再替换目标文件。
- 实际替换方式取决于系统目录提供方能力；不假设所有目录 URI 都支持原子重命名。
- 对已有本地文件，替换前保留可恢复的临时副本；成功后清理，失败时尽可能恢复并明确报告状态。
- 下载失败不得主动删除原有存档；临时文件不参与后续同步扫描。
- 能恢复源文件修改时间时进行恢复；不能恢复时更新本地文件基线与源时间对应关系。
- 下载成功更新文件记录，但不推进“最后完整上传成功时间”。
- 用户跳过的文件保留原样，并在结果中统计；不能把有跳过的任务显示为“全部文件已一致”。
- 远端 Key 必须校验位于当前映射前缀内，转换后的相对路径不得越过本地授权目录。

## 7. Android 目录访问

本项目为 Android 应用，目录访问不能直接套用桌面绝对路径方案。

默认通过系统目录选择器获得目录 URI，持久保存读写授权，并使用支持目录 URI 的文件访问方式。界面展示可读目录名称或路径描述。

受 Android 版本、系统目录选择器及设备权限影响，部分游戏目录可能无法授权。授权失败、目录不存在、不可读写或授权失效时，明确提示重新选择目录，不显示为同步成功。

一期不承诺 Root、特殊存储权限或其他绕过系统目录限制的能力。若实际存档位于系统不允许选择的目录，后续需按目标设备单独确定方案。

## 8. 状态、异常与边界

- 进度展示当前文件、已处理／总文件数、上传或下载状态。
- 结果区分别统计：成功、未变化、用户跳过、失败。
- 空目录或没有匹配文件时，显示“没有需要同步的文件”。
- 处理网络断开、凭证错误、空间不存在、上传失败、远端对象删除、磁盘不足和本地权限异常。
- 不记录密钥、访问令牌或带签名的完整下载链接。
- 不把单个文件成功当作整轮成功；失败项支持重试。
- 用户主动取消时停止启动后续文件任务，保留已完成记录；取消与已开始的安全替换操作协调，避免中途破坏原文件。
- 应用被系统结束后，不显示虚假的运行状态；下次启动提示上次任务未完成，允许重试。
- 本地删除文件不删除远端对象；远端删除对象不删除本地文件。之后下载可恢复远端仍存在的文件。

## 10. 实施顺序

确认后采用以下实施顺序：

1. 增加侧边栏、七牛配置和路径映射页面，接入持久化及目录授权。
2. 完成本地扫描、格式筛选和远端路径映射。
3. 完成首次及增量上传、文件记录和成功水位更新。
4. 完成远端分页下载、时间比较、覆盖确认和安全写入。
5. 补齐进度、错误提示、取消和失败重试。

## 11. 人工验收清单（供你后续校验）

以下为功能核对项，不生成或执行自动化测试代码：

- 侧边栏可以进入“添加路径”，保存后列表可见，重启仍保留配置。
- 首次保存上传所有匹配文件，子目录结构及同名文件映射正确。
- 再次上传时跳过未变化文件，上传新增、更新和之前失败的文件。
- 部分失败、取消或中断后，不错误推进整轮成功时间；重试可以补齐。
- 上传过程中修改的文件不会被错误标记为当前版本已同步。
- 下载缺失或较新的文件可以完成；较旧文件覆盖前必须确认。
- 选择跳过保留本地内容，选择覆盖才替换；未知时间不会静默覆盖。
- 刚下载且未再次修改的文件不会因落地时间变化而立即重新上传。
- 修改映射范围后不会因沿用旧水位而漏传新范围文件。
- 权限失效、网络异常及空间不足时显示真实失败状态，原有存档可保留。

## 12. 本文采用的默认约定

以下为已确认并用于一期实现的默认方案：

1. 使用一个七牛连接配置，多条本地目录映射；远端前缀必填。
2. 目录默认递归，格式按扩展名列表筛选，`*` 代表全部文件。
3. 保存映射后自动上传；后续由用户手动上传或下载，不常驻监听。
4. 上传同名对象直接覆盖；下载较旧或时间不可靠的对象须确认。
5. “最后同步时间”在实现中明确命名为“最后完整上传成功时间”，下载状态另行记录。
6. 远端新旧比较采用源文件修改时间，保存在对象元数据中；对象上传时间仅供辅助展示。
7. 不实现删除传播、版本历史、Root 或特殊目录访问方案。
